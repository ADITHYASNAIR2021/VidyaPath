## Targeted recovery commands

These pages have already been recovered. Repeating the plan is idempotent and does not recreate the original 54,253 vectors. Run it only after the main indexing process has finished, never concurrently with another corpus writer.

```powershell
# Preview page selections and count only; no corpus writes or model calls
node scripts/recover_pdf_pages.mjs --plan scripts/plans/recovery-2026-11-14.json

# Apply new chunks only, using the exact existing cached local embedding model
node scripts/recover_pdf_pages.mjs --plan scripts/plans/recovery-2026-11-14.json --apply
npm run eval:rag:report
```

Recovery validates the selected source paths stay within the public textbook dataset, checks vector-file integrity/model identity, stages new embeddings before corpus writes and backs up existing artifacts. On finalization failure it restores the saved artifacts. Missing model cache fails rather than downloading or switching model spaces. Text recovered from source pages is untrusted academic evidence and remains subject to the runtime safety/quality gates.

## Serving

This is the earlier rebuild snapshot. The later [deployment runbook](./DEPLOYMENT_RUNBOOK.md) supersedes the packaging sizes and serving setup below: textbook gzip and a private E5 service are now supplied, and the deployment gate checks page traces as well as APIs.

The distributed core artifacts total about 56 MiB; the approximately 420 MiB raw vector file is not bundled into Vercel functions. Local creation does not publish the new corpus. Deploy the matching chunk/index/manifest artifacts for BM25, or ingest a new immutable database release and provide a matching E5 query encoder for semantic serving. Never query these E5 documents with MiniLM or NVIDIA embeddings.

On a long-running local Node/Docker host, opt into the matching query encoder with `AI_ENABLE_LOCAL_EMBEDDINGS=1`. Vercel intentionally disables local ONNX inference. Enabling the optional database adds centralized semantic search; the current hybrid implementation still loads local BM25 for fallback, so that switch alone does not remove corpus memory/package costs.
